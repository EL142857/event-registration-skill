# 缴费凭证怎么看

`payment.py` 只会算「应付多少」，凭证图要人（或 Claude 用 Read 工具逐张打开）看过才能下结论。

## 流程
1. 跑 `payment.py`，得到 `out/verdicts.todo.json`：每个待看的人有应付金额、明细、图片路径。
2. 逐个打开图片，按下表判断，把结论写进 `out/verdicts.json`：
   ```json
   { "ab123": {"status": "ok", "paid": "£80", "note": ""},
     "cd456": {"status": "check", "paid": "£60", "note": "选了往返大巴应付 £80，只看到 £60，差 £20 车费"} }
   ```
   key 用 people.json 里的 `k`。
3. 再跑一次 `payment.py`，再 `render.py payment` 出页面。

## 结论怎么选
| status | 什么时候用 |
|---|---|
| `ok` | 转账**成功**页，金额 = 应付，收款人对 |
| `coupon` | 金额 = 应付 − 优惠减免，且写了优惠码（码是否有效需主办方另外核对） |
| `free` | 应付 0（如工作人员不坐车），凭证无所谓 |
| `check` | 其它一切：金额不对、只有确认页/Review 页（还没点确认）、空白图、无关截图、汇款申请书而不是到账记录、看不清、一张图替多人付但说不清是谁…… |

## 常见情况（真实活动里遇到过）
- **少付附加费**：选了大巴但只付了票钱 → `check`，备注写差多少。
- **转账前的确认页**：有金额但按钮还是「Confirm / 确认付款」→ `check`「截图是转账前的确认页，证明不了已付款」。
- **空白 / 纯色 / 无关图片**（课堂照片、文字图）→ `check`「没有转账记录」。
- **一笔替多人付**：金额是两人份 → 找到另一人，两人都备注「由 xx 代付」；说不清是谁 → `check`。
- **多付**：→ `check`，备注可能替别人付了或需要退款。
- **重填后补交凭证**：同一个人所有提交里的图都会合在一起看，以补交的为准。
- **不同人上传同一张图**：`proofs.py` 会标记，两人都要核实。
- **工作人员票**：很多活动规定一律核实（`always_review_tickets`），哪怕凭证看起来没问题。

## 原则
- 不确定就 `check`，备注写清楚为什么、差多少，方便主办方一句话追问。
- 不替用户认定「已付」，也不要编造金额。
- 价格是推断出来的（比如从凭证里反推），要在给用户的回复里说明是推断，请他确认。
